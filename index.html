How a Rust program meets the machine

Rust's ownership and borrowing rules make much more sense once you can picture what they protect. They protect real bytes, at real addresses, inside a process that the operating system and the CPU are running. The picture is built one layer at a time, using the same small program throughout.

There are four layers. Every idea here belongs to one of them, and much of the confusion around "stack", "heap" and "memory" comes from mixing them up. Each layer keeps the same colour everywhere.

  • Rust language — rules the compiler checks before anything runs
  • Compiler & runtime library — machine code, start-up code, the allocator
  • Operating system — processes, threads, address spaces
  • CPU & hardware — registers, caches, address translation, RAM

The route

Each topic answers one question, and each answer raises the next one. Every topic can be read on its own, but they make the most sense in this order. A ✓ next to a number marks a topic you have already opened in this browser.

  1. 01What is a program?The program is instructions and data prepared for running. Text becomes an executable file; the OS turns the file into a running process.Comp
  2. 02How does a CPU run code?The CPU runs machine instructions, using registers and execution units.HW
  3. 03What does a program get when it starts running?The operating system starts programs and manages resources. A process is a running instance with its own address space.OS
  4. 04What is inside a process's address space?Virtual memory is the address space a process uses: code, data, heap, libraries, stacks.OS
  5. 05How does a virtual address reach physical RAM?Physical RAM is real hardware memory. The OS and the MMU map virtual pages onto its frames.HWOS
  6. 06What do threads share, and what does each keep to itself?A thread is a path of execution in a process, with its own execution state and its own stack.OS
  7. 07Where do the bytes of one memory read come from?Registers and caches let the CPU work without going to RAM for every value.HW
  8. 08What happens on the stack when one function calls another?The stack holds the active calls of one thread, in order.Comp
  9. 09Where does a Rust value live, and what does Box change?Stack and heap are two ways of organising memory, not two kinds of chip.RustComp
  10. 10What is a Vec made of, and what happens when it grows?A handle on one side, a contiguous buffer on the other.RustComp
  11. 11Who frees a String's memory?Ownership is a language rule about responsibility. It does not replace the OS or the CPU's memory system.Rust
  12. 12How can code use a value it does not own?Borrowing: references, the two rules, and what lifetimes describe.Rust
  13. 13What does a loop over a Vec actually hand you?iter, iter_mut and into_iter, seen in memory.Rust
  14. 14How do memory bugs happen, and what does Rust change?Stack overflow, out-of-bounds access, use-after-free.Rust
  15. 15What happens, layer by layer, when total(&scores) runs?Every layer at once, one event at a time.RustHW

How to read the pictures

Most topics have a diagram with Back and Next buttons. Each step changes one thing, and a sentence under the buttons says what changed. The arrow keys also step through a diagram once it has focus. Without JavaScript, the diagrams show their finished state with every step written out below.

Some numbers come from a real program, built and run on Linux, x86-64, with rustc 1.98.1. Those are marked as real, and they will be different on your machine. Other numbers are made up to keep an example small, and those are marked as illustrative. Each diagram also has a short note of what it leaves out.

Facts come with a link to where they were checked, such as Vec docs. Links marked Wikipedia are for further reading on a general idea. The full list of sources, the glossary and the concept map are in the reference folder.
